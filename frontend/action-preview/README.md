# 鸿心 · 课程行动前端设计预览

日期：2026-11-03。新产品方向的前端提案，独立于旧版复刻原型。直接用现代浏览器打开index.html；无需安装依赖或构建。

## 本版范围

- 今天：课程背景、四项行动、进度、指定阅读。
- 早起：模拟未到/开放/过期三态；北京时间05:31:00—05:31:59为用户已确定窗口。正式状态必须由服务端提供。
- 晨跑：本地JPG/PNG图片预览；固定示例识别结果，可编辑距离/分钟/步数并模拟记录。这些指标是界面提案，未审定。没有OCR，没有上传。
- 阅读：本地开始/暂停/结束计时，单独确认指定任务完成后保存模拟记录。离开页面暂停；未实现后台计时、防作弊或指定阅读材料。
- 拜访：确认弹窗后模拟记录一次自主申报；不填写客户信息。当前单次演示不代表每天只能一次。
- 课程：课程与每日行动任务关联。
- 排行：小组/企业/全省/全国及项目切换的布局，使用同一组固定示例数据。综合行动仅是标签提案，没有积分、算法或真实名次。
- 我的：本次模拟记录与行动进度。刷新页面清空，不保存账号数据。

## 已确定与未确定

已确定：面向其他企业员工，后续多企业扩张；课程强相关；5:31整分钟窗口；晨跑截图+识别方向；阅读时长与指定/团队任务；拜访一键自主申报。

未确定：企业配置方式、增写项目、排行榜对象/周期/公平比较/得分、图片识别字段与校验、阅读有效时长、任务完成标准、拜访每日次数、运营后台。不要将本版的模拟课程名称、组织、任务、人物、章节或天数当成业务要求。

## 给WorkBuddy的后端接入边界

请保留本版作为可视化参考，先提出接入方案，不把DOM里模拟数据当成正式数据模型。

1. 身份、企业/课程/小组归属由可信服务端提供，跨企业访问必须校验。
2. 今日任务及完成状态由接口提供，不能按前端四个布尔值判定有效完成。
3. 早起校验使用服务器时间和约定的业务时区；提交去重、网络延迟及结果反馈策略需明确。
4. 图片上传、OCR识别、识别失败、用户确认/修改应分阶段处理，保留识别来源和修改标记；OCR不证明运动真实性。
5. 阅读记录分开存时长、任务关联和完成声明；前端计时不等于有效阅读时间。
6. 拜访为员工自主申报，不宣称经过客户或位置验证；次数政策待确认。
7. 排行算法及统计周期未定，不能根据示例数值反推业务公式。
8. 所有写入应返回权威状态并防重复请求；权限、审计和错误恢复由正式后端落实。

## 验证记录与限制

实际浏览器走通：早起开放状态记录；晨跑示例值确认；阅读计时/结束/任务确认；拜访确认；个人页显示4条对应模拟记录。排行全国/阅读切换可见。320和390像素宽度首页未发现文档横向溢出。

## 团队流程补充

底部新增团队主入口。默认未加入团队：首页显示加入引导，小组排名为空。可按名称/邀请码搜索虚构团队、进入详情、模拟加入；也可填写名称、20字内口号、城市和当前课程，模拟创建。加入/创建后首页、阅读任务、个人资料显示关联团队。团队页包含详情、部分成员和模拟邀请入口。

不自动转队、不假定多团队规则；已有团队时阻止本原型创建第二个或切换到其他团队。正式创建/加入权限、审核、邀请、跨企业可见范围及退出流程尚待确认。
