# 后端最小闭环 · 怎么跑起来

这不是生产服务。它跑在你自己的电脑上，用一个 SQLite 文件存数据，用来验证接口、权限和统计口径。

## 需要什么

只要 Node.js ≥ 22.5（本机已装 22.22）。**不用 npm install，零第三方依赖。**

## 三步

```bash
cd server
npm run seed     # 写入虚构数据（两家企业、10 个用户、4 支队伍、16 条记录）
npm start        # 启动，默认 http://127.0.0.1:8787
```

然后浏览器打开 **http://127.0.0.1:8787/** ← 那就是演示页。

## 演示页能做什么

| 区域 | 你会看到 |
|---|---|
| 选择身份 | 10 个虚构账号，切换即换身份 |
| 今日行动 | 点「提交」真的写库，刷新后还在 |
| 我的记录 | 客户端时刻、状态、指标 |
| 排行 | 小组内 / 企业内 × 早起 / 晨跑 / 阅读 × 今天 / 本周，真实计算 |
| 团队 | 列表与加入（同一企业才能加） |
| 权限演示 | 用员工身份点「读全企业记录」会返回 403，用管理员身份能读 |
| 最近请求 | 每次调接口都记一行，证明不是假数据 |

## 几个刻意的行为

- **现在点「早起」会被拒**（422 不在窗口内）。这是真实行为。想看成功的样子，勾上"按 05:31:20 提交"，它会落库但标记为**待核**——因为客户端时刻和服务端差了 8 小时。这正是 Q3 决策（用客户端时刻判定）的代价，不是 bug。
- **晨跑提交后会进待核**，因为 OCR 是模拟的，系统会打 `ocr_is_mock`。打这个标记是为了不让模拟识别混进真实数据。
- **拜访一天只能记一次**，第二次返回 409。次数规则还没定，1 次是临时默认。

## 数据在哪

`server/data/hongxin.db`（已加入 .gitignore，不会提交）。想清空重来：

```bash
npm run reset
```

## 接口清单

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/health` | 健康检查 |
| GET | `/api/meta` | 演示账号与可用指标（无需鉴权，仅本地演示） |
| GET | `/api/me` | 当前身份与团队 |
| GET | `/api/today` | 今日任务 + 完成情况 |
| POST | `/api/actions` | 提交行动（要 `idempotencyKey`） |
| GET | `/api/records` | 我的记录 |
| GET | `/api/teams` | 企业内团队 |
| POST | `/api/teams` | 创建团队 |
| POST | `/api/teams/:id/join` | 加入团队 |
| GET | `/api/rankings` | `scope=team\|enterprise&metric=…&period=day\|week` |
| GET | `/api/admin/records` | 全企业记录（仅管理员） |
| GET | `/api/admin/export.csv` | 导出（仅管理员，写留痕） |

鉴权头：`X-Test-User: u_zhou`（**测试适配层，正式版必须换掉**）。

## 没做的

真实微信登录、图片上传与 OCR、阅读心跳、审核界面、排行快照、后台页面、部署。

口径定义见 `docs/ACTION-METRICS.md`。
