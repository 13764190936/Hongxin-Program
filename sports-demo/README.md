# 鸿心运动打卡 · 一次性本地演示

这是一个**只用于演示**的独立小项目：Node 内置 HTTP 服务 + 原生 HTML/CSS/JS，零依赖、无登录、无数据库、无外部付费 API。

> DEMO 状态：虚构公司/身份/数据；步数为模拟微信快照；跑步截图为 MOCK 分析，不做真实 OCR、不接入微信；数据只在内存，重启即重置（演示日期也恢复为真实日期）。

## 快速启动

要求 Node.js ≥ 18（本项目在 Node 24 上开发验证），不需要 `npm install`。

方式一（macOS 双击）：

- 双击 `启动演示.command`
- 脚本会自动找到 Node、启动服务、把日志写入 `.runtime/service.log`，并打开浏览器（本任务执行时未自动打开）。

方式二（终端）：

```bash
cd sports-demo
node server/index.js
# 或 npm start
```

默认地址：<http://127.0.0.1:8790>，只监听 `127.0.0.1`。端口可用环境变量覆盖：

```bash
PORT=8899 node server/index.js
```

停止：在脚本窗口按 `Ctrl-C`；若服务是后台启动的，执行 `kill "$(cat .runtime/server.pid)"`。

## 演示内容

- 一家虚构公司、两个团队、四名学习者：
  - 鸿风先锋队：林晓（产品）、周博（研发）
  - 鸿风追风队：陈晨（设计）、丁一一（运营）
- 页面顶部有 DEMO / MOCK 标识、当前服务端日期和演示身份切换器。
- 每日个人榜 / 团队榜 × 步数 / 跑步距离，共四种视图。
- 历史总步数只在“我的今日状态”中展示，不参与任何排名。
- 种子数据包含今天和前两天步数，以及部分历史/今日跑步记录；默认身份“林晓”今天没有跑步记录，方便直接上传截图体验。

### 步数（模拟微信快照）

- 页面输入的是**当日绝对累计值**，不是增量。
- 同一天先提交 6000、再提交 8000，服务端保存 8000；不会变成 14000。
- 演示策略是“最后一次绝对快照生效”，因此后提交一个更小的值也会覆盖（例如 8000 后提交 5000 得 5000）。这只是演示口径，不校验真实微信数据。
- 当天最终快照 = 当天步数；个人历史总步数 = 各天最终快照之和。
- 页面“同步模拟步数”只是模拟来源，不读取手机或微信。并发写仍按“身份 + 路由 + 幂等键”去重。

### 跑步打卡（显式 MOCK）

- 必须选择本地截图文件上传；页面用 `FileReader` 预览，图片不会发送到第三方。
- 服务端校验解码后的真实字节：
  - 文件头必须是 PNG 或 JPEG（仅改扩展名无效）；
  - 解码后 ≤ 2MB；
  - 必须提供有限的、大于 0 的模拟距离（公里）和模拟时长（分钟）。
- 对图片字节计算 SHA256。**演示默认在全局范围去重**：同一张图（完全相同的字节）跨人、跨天再次提交都会被拒绝。
- 每人每天只允许一次跑步打卡，换一张新图也不能在同一天重复计分。
- 唯一性在分析器返回后、写入前同步复核（检查与插入之间没有 await）。因此两个人同时提交不同图片时只有一条能成功；同一张图并发提交也只有一条能成功。
- 图片本身不能证明真实跑步；页面和接口返回都明确标注“模拟识别结果 / MOCK”，不做真实 OCR。

### 每日榜与团队聚合

- 榜单只统计当前演示日；进入“下一天”后旧日榜清空，个人历史总步数保留。
- 团队日榜默认按团队内当日有数据成员的数值**求和**（演示默认）。
- 数值相同并列同一名次，展示顺序按名称排序；并列后名次跳号（如 第 2、第 2、第 4）。
- 跑步距离榜的数值是当天该成员唯一一次跑步的公里数；团队为成员公里数求和。
- 聚合策略在 `server/config.js` 的 `teamAggregation` 中切换，`rankService` 内已预留 `avg` 示例。

## 服务端日期与重置

- 日期由服务端按 `Asia/Shanghai` 计算，客户端不能提交日期。
- “下一天”只推进本进程内的演示日期，所有 API 统一使用它；重启服务恢复真实日期。
- “重置演示”需要确认字符串 `RESET`，会清空内存数据、恢复真实日期并重新播种。
- 页面上的“下一天 / 重置演示”使用页面内二次确认（确认 / 取消两个按钮），不调用原生 `window.confirm`，不会阻塞自动化。
- 身份切换、进入下一天或重置后，未提交的截图、预览、打卡结果和距离/时长草稿都会被清理；写入进行中会暂时锁定身份切换和这两个操作。
- 数据保存在进程内存，重启即重置；`data/` 目录预留但当前未使用。

## 接口

写接口都需要请求头 `Idempotency-Key`，并按“身份 + 路由 + Key”保存结果：

- 相同 Key、完全相同请求体：返回原结果（`replayed: true`），不产生新记录。
- 相同 Key、不同请求体：`409 IDEMPOTENCY_CONFLICT`。
- 并发相同 Key、相同请求体：只执行一次，后到请求等待并共享同一条结果；并发相同 Key、不同请求体：后到请求立即 409，即使第一个仍在处理中。
- 处理失败不会缓存错误或占用 Key，重试会重新执行；已成功的结果仍按上面的规则回放。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/health` | 存活、演示日期、PID |
| GET | `/api/meta` | 日期、公司/团队/身份、演示说明、适配器信息 |
| GET | `/api/identities` | 演示身份列表 |
| GET | `/api/me` | 当前身份今日步数、历史总步数、今日跑步；需 `x-demo-user` |
| GET | `/api/boards?metric=steps\|run` | 当日个人榜与团队榜 |
| POST | `/api/steps/mock-sync` | 提交当日绝对步数快照；需身份与幂等键 |
| POST | `/api/runs` | 上传截图 + 模拟距离/时长；需身份与幂等键 |
| POST | `/api/demo/next-day` | 演示日期 +1，仅本机 |
| POST | `/api/demo/reset` | 重置演示，`{"confirm":"RESET"}`，仅本机 |

身份使用请求头 `x-demo-user`（演示开关，不是认证）。未知身份返回 `403 IDENTITY_UNKNOWN`，缺失返回 `401 IDENTITY_REQUIRED`。

### 主要错误码

`STEPS_INVALID`、`DISTANCE_INVALID`、`MINUTES_INVALID`、`IMAGE_REQUIRED`、`IMAGE_ENCODING_INVALID`、`IMAGE_TYPE_INVALID`、`IMAGE_TOO_LARGE`、`BODY_TOO_LARGE`、`RUN_ALREADY_CHECKED_IN`、`IMAGE_ALREADY_USED`、`IDEMPOTENCY_KEY_REQUIRED`、`IDEMPOTENCY_CONFLICT`、`IDENTITY_REQUIRED`、`IDENTITY_UNKNOWN`、`METRIC_INVALID`、`RESET_CONFIRM_REQUIRED`、`LOCAL_ONLY`。全部返回中文 `message`。

## 后续扩展缝（当前均未实现）

1. **真实微信步数来源**：替换 `server/adapters/mockStepSource.js`，保持 `snapshot()` 返回结构；需要微信授权、后端签名校验和防篡改。
2. **真实 OCR**：替换 `mockRunAnalyzer`，`analyze()` 返回 `mock: false` 和识别依据；需要图片预处理、模型供应商与失败降级。
3. **感知哈希/图像相似去重**：当前仅对完全相同的字节做 SHA256；换图后改像素即可绕过。生产应加 pHash/dHash 等近似去重并设阈值。
4. **认证与组织权限**：当前 `x-demo-user` 只是演示身份头；生产需要登录、会话、组织/团队数据隔离与管理员权限。
5. **持久化**：`store.js` 的方法签名不变，替换为数据库实现；注意按日快照的唯一约束、幂等表唯一约束和图片去重索引。
6. **团队聚合**：`rankService` 已按策略查表调用，可增加平均、去极值、按人数加权等；需要产品确认口径。
7. **跑步阈值与真实性**：距离/时长目前只校验“有限正数”，没有配速、上限、GPS 或设备可信度判断；这些阈值尚未确定，不应在演示中假装已校验真实跑步。
8. **图片存储**：当前只保存 SHA256、大小、类型，不保存图片文件；生产需明确隐私、保留期限和访问控制。

## 安全边界（演示级）

- 仅监听 `127.0.0.1`，不绑定公网；静态文件做了目录穿越防护。
- 请求体上限 4MB，图片解码上限 2MB；错误信息为中文，不输出堆栈到客户端。
- 页面所有动态文本使用 `textContent` 渲染；CSP 只允许同源脚本/样式与 data/blob 图片。
- 不保存原始截图；日志不打印图片和身份敏感信息。

这些措施只适用于本地演示，不能当作生产安全设计。
