# 开发重塑总体规划

- 日期：2026-11-03
- 触发：负责人反馈"太简陋、根本没法用，需要完全重塑开发逻辑，一点一点每个功能开始修"
- 结论：**同意。现在的做法有问题，问题不在"做得不够快"，在于顺序错了。**

---

## 1. 现状诊断：为什么会简陋

不是"没花时间美化"，而是四层缺失，导致每加一个功能都只能手写一遍。

| # | 问题 | 证据 | 后果 |
|---|---|---|---|
| 1 | **没有设计系统** | 全站颜色写死 6 个变量、字号只有 4 级、圆角到处 `12px/15px/18px` 混用 | 每个页面长得像不同人做的 |
| 2 | **没有组件层** | 卡片、行动卡、榜单行、表单都是页面内联字符串，改一处要改 4 处 | 不敢改，只能加 |
| 3 | **没有状态矩阵** | 只画了"成功"一条路。提交中无视觉、失败只有 toast、空态只有"暂无数据" | 一操作就露馅 |
| 4 | **单文件混写** | `index.html` 一个文件塞了 CSS + DOM + 900 行 JS | 任何改动都在 900 行里找，风险高，所以只敢"能跑" |
| 5 | **验收标准太低** | "接口通了""能点了"就算完成 | 页面从来没被当产品验收过 |

**还有一类不是"简陋"，是"没做"**，必须分开记账：

- 没有登录/注册（现在靠请求头传用户 id）
- 没有真实图片上传与识别
- 没有课程内容（视频、章节、阅读材料）
- 没有审核流程（待核记录只能躺在库里）
- 没有小程序端

这五项不该被"美化"掩盖，必须单独排期。

---

## 2. 重塑原则（五条，之后所有决定按这五条判）

1. **先有标准，再有页面。** 设计令牌和组件先落地，任何页面只允许用组件拼，不允许手写新样式。
2. **一个功能做透，再下一个。** 禁止"五个 tab 一起改一点"。每个功能必须走完：现状→目标→改→自测→记录。
3. **状态先于内容。** 每个页面先交五种状态（加载/空/错误/无权限/成功），再补内容。
4. **视觉验收可勾选。** 每页有一份清单（间距、层级、字号、点击反馈、动效），逐条打勾才算完。
5. **不加速假东西。** 假 OCR、假课程、假登录一律标在页面上，不许混进"已完成"。

---

## 3. 目标架构：拆开，但不引入构建工具

关键取舍：**保持"双击就能跑、零依赖"**，用原生 ES Module 拆文件，不引 webpack/vite。这样部署仍然是一个静态目录，运维为零。

```
server/public/
├─ index.html              # 只留骨架 + <script type="module">
├─ tokens.css              # 设计令牌：颜色/字号/间距/圆角/阴影/动效时长
├─ base.css                # 重置、排版、通用工具类
└─ src/
   ├─ api.js               # 接口封装（含测试身份头、错误归一）
   ├─ state.js             # 单一状态对象 + 订阅
   ├─ router.js            # tab / 子页切换
   ├─ ui/
   │  ├─ task-card.js      # 行动卡（今天页 4 张）
   │  ├─ rank-row.js       # 榜单行
   │  ├─ sheet.js          # 底部弹层
   │  ├─ toast.js
   │  ├─ skeleton.js
   │  ├─ empty.js          # 空态（带插画 + 主行动）
   │  ├─ error.js          # 错误态（带重试）
   │  └─ stepper.js        # 步骤条（打卡流用）
   └─ pages/
      ├─ today.js  early.js  run.js  read.js  visit.js
      ├─ course.js  rank.js  team.js  mine.js
```

**硬规则**：`pages/*.js` 里**不允许出现颜色值和 px 字号**，只能用 `var(--...)`。这条能用脚本检查，我会加进自测。

## 4. 设计系统（阶段 A 的产出）

### 4.1 令牌（先定这套，全站唯一来源）

| 类别 | 值 |

## 5. 逐功能修复清单

每一块都按"现状简陋点 → 修成什么 → 怎么算完成"写。**顺序就是你点的顺序，可以从任意一块开始。**

### F1 今天页

- **简陋点**：进度条 3px 无刻度；四张卡只有文字，没有图标语义；没有"今日还剩几件"的引导；没有下拉刷新
- **修成**：顶部一张"今日进度"卡（环形或分段进度，4 段对应 4 项）；行动卡带图标 + 状态徽标 + 一键进入；底部"还剩 N 件，约 X 分钟"；下拉刷新
- **完成**：5 种状态齐、下拉可刷新、点击进详情不丢状态

### F2 早起（最需要信任感的一屏）

- **简陋点**：一个时间大字；不显示服务器时间；窗口状态只有三种颜色，没有解释；没有"我错过了什么"
- **修成**：服务器时间 vs 本地时间并列（告知以哪个为准）；窗口前后各 5 分钟的倒计时；错过时给出"明天 05:31"的提醒入口；成功页显示记录号与两个时刻
- **完成**：窗口前/中/后/已打卡四态可点、倒计时准确、拒绝有解释

### F3 晨跑

- **简陋点**：虚线框不会真的选图；三个 input 是裸输入；没有识别过程；提交后一定进待核（因为假 OCR）
- **修成**：真实选图 + 预览 + 重新选择；三步步骤条（选图 → 识别 → 确认）；识别过程有 loading 与"这是模拟识别"明确标注；数据可编辑且标明"你改过哪些"
- **完成**：能选中本地图片并预览、三步可回退、模拟标记可见

### F4 阅读

- **简陋点**：计时器纯数字，无进度环；结束阅读后才有勾选，顺序反了；没有正文
- **修成**：圆环计时（目标 15 分钟）；暂停/继续不丢时长；正文区（示例文本占位并标注）；完成勾选与时长分开呈现；离开页面提示"计时已暂停"
- **完成**：计时可暂停、退出再进不丢、勾选与时长独立

### F5 拜访

- **简陋点**：只有一个大符号和一个按钮，信息量过低
- **修成**：说明"这是什么、为什么记、谁看得到"；确认弹层展示"将记录：今天 1 次"；完成后显示次数与时间
- **完成**：二次确认、重复提交被 409 拦并解释

### F6 排行

- **简陋点**：裸表格；无头像；无"我的名次"常驻条；切换条件时无 loading；并列看不出来
- **修成**：前三名视觉区分（不改数据，只改展现）；我的行固定吸底；切换时骨架屏；并列显示"并列"标记；空榜给引导（未入队 → 去加入）
- **完成**：三种指标 × 两种范围 × 今天/本周，每组合都有正确空态与加载态

### F7 团队

- **简陋点**：纯文字列表，看不到人；没有加入/邀请流程
- **修成**：成员头像墙；邀请码可复制；加入流程（搜索 → 详情 → 加入 → 结果）；团队内排名摘要
- **完成**：能加入（模拟）、能复制邀请码、加入后榜单出现

### F8 我的 / 记录

- **简陋点**：记录列表没有图标、没有状态解释、没有详情
- **修成**：记录按日期分组；每条可展开看指标与记录号；状态有图例；切换身份移到"演示设置"里并写明后果
- **完成**：记录可展开、分组正确、身份切换有提示

### F9 主管与导出（现在只有一张表）

- **简陋点**：只有表格；没有筛选；没有"数据截止时间"
- **修成**：四个指标卡 + 筛选（日期/项目/状态）+ 分页 + 导出（带留痕说明）
- **完成**：筛选生效、导出文件与筛选一致

## 7. 需要你先定三件事

### Q1 视觉方向（三角）

现在这套"纸感 + 墨绿 + 大标题"是我的默认。三个方向：

- **A 保持现状深化**：纸色底、墨绿、克制的衬线感。优势是已经有点识别度，改造成本最低。
- **B 企业级稳重**：白底为主、蓝灰体系、信息密度高、接近企业微信/钉钉。客户是 HR 时更"像正经系统"。
- **C 运动激励感**：深色卡 + 亮色强调 + 数据可视化更强，接近 Keep。员工更愿意打开，但 B 端客户可能觉得"不够严肃"。

你选 A / B / C，或者说"你决定"。

### Q2 逐块顺序

默认按 F1 → F2 → F3 → F4 → F5 → F6 → F7 → F8 → F9。要不要先做别的（比如先 F6 排行，因为它是给客户看"数据真的在算"的地方）？

### Q3 假东西的处理

现在有三处是假的：OCR 识别、课程内容、登录。三种处理方式：

- **标清楚**（页面上写"模拟"）——现状，最诚实但最不"完整"
- **做成可配置**：留接口，演示时开关，客户看不到
- **先补真的**：OCR 要接服务（有成本），登录要企业微信/微信（要资质）

我建议第一项保持"标清楚"，第二和第三排到阶段 C。但如果你要拿去投标或签约，可能需要第二项。你定。
