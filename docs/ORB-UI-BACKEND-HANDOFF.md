# 球体任务 UI：交给 WorkBuddy 的后端说明

日期：2026-11-07。界面在 frontend/orb-preview/，使用原生 HTML/CSS/JS。

## 本轮已确认

首页横向切换任务球体，点击当前球体进入该任务子页。跑步页先截图操作，再跑步榜；左上管理个人资料。右上“排行榜”是各项目榜单统一入口，切换跑步、步数等，**不新增综合分**。保留跑步和步数的个人/队伍日榜；历史累计步数仅展示于个人资料。

## 实现边界

先为独立 sports-demo/ 接入此界面，保持主产品 server/ 不动。后续合并主产品须另行设计确认，不复制两套判定规则。保留现有演示身份与内存存储，不引入用户数据库、真实微信接入或真实 OCR。本原型不调用 API；所有示例数据仅用于设计演示，不能当作服务器事实。

app.js 中 demoAdapter 是替换边界。将数据读取、截图提交、步数同步放入独立 adapter；UI 只消费规范化结果，不在界面中写完成或排名规则。可使用依赖注入或一个 adapter 模块切换本地演示和接口模式。保留原型目录用于设计验收；集成版本另交付可运行入口及说明。

## 现有接口复用

实施前核查 sports-demo/server 的当前实际代码，不直接照此文档覆盖。

| 页面动作 | 已有 API | 接入要求 |
| --- | --- | --- |
| 当前资料、日步数、历史累计 | GET /api/me | 使用现有 x-demo-user 演示身份；不由客户端决定身份权限 |
| 跑步/步数个人与队伍榜 | GET /api/boards?metric=run 或 steps | 返回两种范围；界面切换对应数据，不请求综合分 |
| 模拟步数同步 | POST /api/steps/mock-sync | steps 为当天绝对值；携带 Idempotency-Key，重复同步不重复累计 |
| 跑步截图 | POST /api/runs | 现有 imageBase64、filename、distanceKm、minutes；Idempotency-Key 绑定一次提交，同一提交重试复用 |

现有跑步接口仍要求手填数值，与新 UI 仅选截图存在差异。演示接入可使用独立、标注清楚的模拟识别 provider，从演示样本生成距离/时长；禁止将固定值藏在真实提交逻辑里并宣称 OCR 已完成。不仅凭手填里程完成打卡。真实识别上线前另行确认识别服务和风险策略。

## 建议补充的接口契约（尚未实现）

GET /api/tasks：返回稳定任务 id（early/run/steps/read/visit）、enabled、当天状态及禁用原因。首页文案只渲染服务器状态；未定项目明确未开放。

PATCH /api/me：只允许更新展示名等已批准字段，长度与空白校验由服务器负责；演示身份不能修改公司、队伍、权限。若此次不做该接口，资料只读，并移除集成版保存按钮，不能假保存。

可统一 adapter 的返回结构：
- me: {id, displayName, teamName, dailySteps, lifetimeSteps}
- task: {id, enabled, status, reason}；status 至少区分 not_started / processing / completed / rejected。
- board: {metric, date, timezone, scope, rows:[{rank, displayName, teamName, value, unit, isMe}], ruleLabel}
- submission: {submissionId, status, reason, recognizedMetrics}；只有后端 completed 才展示完成。
- error: {code, message, retryable}；界面显示可操作原因。异步识别需另加查询提交状态接口，不能无限等待。

## 必须保持的约束

- 服务端统一业务日期与时区（项目现有约定优先），日榜不混入历史累计值；跨日不重复计入历史累计。
- 无用户数据库仍需验证演示身份及队伍访问范围；未入队用户队伍榜返回空与原因，不能返回其他队伍数据。现有测试曾报告这一处失败，实施时核查并修复，不声称本轮已修复。
- 上传在服务端限制大小、真实文件格式、损坏文件；相同截图摘要重复检查复用现有逻辑。内容相似或篡改识别属于后续能力，不能声称哈希能解决。
- 服务器失败、重复截图、处理中、无榜单、网络失败都有明确状态；错误不改变完成状态。切换页面时异步响应不能更新错误任务。
- 队伍合计/平均、跑步有效阈值、同分规则与排名可见范围继续遵循客户问题表，演示规则显式标明，不新增业务承诺。
- 主管提醒与机构数据后续扩展；此次不新增培训机构后台 UI。

## 验收交付

提供运行方法、实际改动清单和验证结果；确认跑步提交→后端判定→个人/队伍榜更新；重复同步不累计；重复图片拒绝；失败不误标完成；跨日归零日榜；历史累计仅资料展示；身份与队伍隔离。手机与桌面都保留球体选择、上下页面关系、减少动态效果与返回选中项。

不要 push、部署或重构主产品。未确认事项写客户问题表。需要与用户确认的产品变化集中提出，不反复来回让 Codex 转发实现日志。

## 最新外观约束
用户已改为黑白平面界面、亮蓝色主要按钮与选中控件，不使用绿色背景、渐变圆形、投影和高光。日夜主题和本机时钟只属于展示层，禁止用设备时间决定打卡日期或完成。当前网页原型并非微信小程序代码；若用户确认小程序实施，需要单独转换页面与平台适配，不能宣称网页即小程序。

最新用户修订：项目圆形各有独立平面配色（早起琥珀、跑步橙、步数青蓝、阅读紫、拜访玫红），当前和邻项都保留项目色，用大小、位置、文字及图标识别；背景仍黑白、操作仍亮蓝，不用光影。UI 参考 ChatGPT、苹果、DeepSeek 的简洁层级与留白。此条覆盖此前项目圆形黑白/描边的约定。

最新用户微调：项目圆形允许少量光影与轻微厚度；按钮改柔和圆角（主要16px、其他12px），不再使用4px方角。类别配色、黑白背景与亮蓝色主要操作保留。以此条覆盖此前完全无光影的约束。

最新配色修订：项目提高明度、降低饱和度，早起奶油黄、跑步浅蜜桃、步数雾蓝、阅读淡薰衣草、拜访柔粉；图标和名称使用深色同色系。每个圆形左上柔光、下方小柔影，保持黑白背景和亮蓝操作按钮。此条覆盖之前较暗的浓色项目配色。

## 液态玻璃视觉试版（待用户选定）
当前 index.html 在 app.css 后加载 glass.css：浅色项目透色、背景柔化、细亮边、局部反光和向下柔影；黑白页面、亮蓝主要操作与原有交互保留。圆形背后用轻量色带作为透光参照。使用网页 CSS 近似玻璃观感，并非苹果原生 Liquid Glass 或真实物理折射。提供减少透明效果与不支持 backdrop-filter 时的实色回退。移除 index.html 中 glass.css 的引用即可恢复上一版，不需要修改后端。此为视觉比较试版，未确定为最终风格。

集成界面时将 glass.css 一并作为可替换样式层保留；后端不承载玻璃效果或本机时钟判定。

最新首页交互：移除独立的蓝色进入按钮，项目下方改为项目用途说明、体验状态和轻量下滑提示；点击当前圆形、提示文字、PageDown 或首页底部向下滚动可进入。手机在圆形/信息区域向下拖动超过65px进入，横向滑动仍切换项目；短屏可从其他页面区域正常滚动。任务页上传、同步等操作按钮保留。

最新返回交互：任务页说明下方提供“在这里上滑，返回项目选择”手势区，向上滑动超过65px返回并保留当前项目。上传区、表单和排行榜仍正常滚动，不全页截获上滑。桌面在任务页顶部向上滚动或按PageUp同样返回；原返回按钮和Escape保留。手机手势需真机验证，不能把桌面滚动核查称为手机触摸验收。

最新气泡内容试版：移除项目气泡内的自绘简笔图标，以32px、600字重的项目名称居中展示，邻项随圆形整体缩放。玻璃材质、浅色分类和导航手势保持不变；导航与主题等功能图标仍保留。

用户纠正：保留项目图像，已恢复并重画统一圆润线条图标：日出、跑步路线、脚印、书本、公文包；名称16px、图标58px、描边1.45。此条取代纯文字气泡试版。

手势方向最终修正：手指上滑进入任务子页（dy<-65），手指下滑在返回区回到首页（dy>65）；进入页面向上运动，返回向下运动。鼠标向下滚动进入/向上滚动返回沿用浏览器滚动语义。已同步服务器客户演示。

用户最新决定：取消任务页滑动返回及提示、顶部滚动返回和PageUp返回；保留点击返回首页与Escape。首页上滑进入子页面不变。

## 2026-11-08 最终视觉方向：Flat Vector Design
用户明确指定现代扁平矢量：几何形、纯色填充、简洁轮廓，可有轻阴影，不拟物、不手绘、不用真实材质。当前 index.html 已停用 glass.css；项目为原浅色独立纯色，统一14px控件圆角、统一图标描边与比例；仅项目气泡保留轻阴影。保留手机196px气泡/48px图标、上滑进入、按钮返回、独立项目榜与示例数据边界。此项覆盖旧玻璃/高光/纹理试版约定。
