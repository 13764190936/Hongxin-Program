# 课程行动平台：最新需求与后端接手说明

日期：2026-11-03。此文记录负责人在旧版调研之后确认的新方向。先读本文，再读历史PRD；旧版功能清单仍是调研参考，不代表新版必须逐项照搬。

## 1. 当前产品方向

面向其他企业员工，后续可能服务大量企业。课程强相关的每日行动打卡是主线：打开平台→看到课程任务→上传/记录→后台收到数据→按规则统计并生成表格→团队与区域排行。

最新前端：`frontend/action-preview/index.html`。直接用浏览器打开，无依赖安装。配套说明：`frontend/action-preview/README.md`。旧`prototype/index.html`保留为上一轮功能复刻/流程原型，不要把它当最新首页。

新前端仍为HTML模拟，不是小程序工程。后端接入及目标小程序客户端的正式实现需要分别开展，不宣称HTML可直接打包成小程序。

## 2. 负责人已确认

| 项目 | 明确结论 |
|---|---|
| 服务对象 | 其他企业员工，预留多企业增长能力 |
| 产品主线 | 课程关联行动、打卡上传、后台接收和统计表格 |
| 早起 | 北京时间每日05:31:00—05:31:59整分钟；由服务器判定，前端时钟不作权威依据 |
| 晨跑 | 希望上传运动图片并自动提取信息；字段/凭证支持范围尚未决定 |
| 阅读 | 记录阅读时长，并完成指定内容或团队任务；有效时长与完成验证方式待定 |
| 拜访 | 点一下记录，不要求拜访详情；次数限制与审核未定 |
| 团队 | 必须有创建和加入UI，已补；组织、课程、小组关系及正式权限规则未定 |
| 排行 | 需要小组内、较大范围、省级、全国等范围；对象、得分、周期和公平比较规则未定 |
| 企业配置 | 自行选择打卡项目等配置后续讨论，不能默认已批准复杂配置平台 |
| 增写 | 暂缓，含义尚未确认 |

## 3. 前端目前能演示什么

五个入口：今天、课程、排行、团队、我的。

- 早起时间状态切换及模拟完成。
- 晨跑选择本机JPG/PNG图片、查看固定示例识别值、编辑并记录。**没有OCR与文件上传**。距离、分钟、步数是前端提案，不是已确定最终字段。
- 阅读本地计时、暂停/结束、单独勾选完成任务。没有持续后台计时、防作弊或真实指定材料。
- 拜访确认后记录一次自主申报。单次演示不等于每日一次业务规则。
- 默认没有团队。可按名称/示例邀请码查询虚构团队、详情/成员、模拟加入；可创建包含名称/口号/城市/当前课程的模拟团队。字段必填性、单一团队、审核和创建者能力属于预览限制，不能直接照搬成后端政策。
- 加入/创建后关联首页、阅读、个人资料；未加入时小组榜为空。
- 模拟记录只在页面内存；刷新清空。排行切换使用固定示例，不计算真实名次。

## 4. 建议后端开工范围（可先在本地或隔离测试环境实现）

先交付一个可验证的小闭环：测试身份与企业归属→课程/任务→创建/加入团队→提交一条行动记录→后台查询→导出测试统计表。真实微信身份、云资源和OCR供应商接入另列步骤；没有真实环境时可使用清晰标记的测试适配层，不把测试身份当正式鉴权。

建议任务顺序：

1. 检查现有仓库代码与运行条件，提出后端技术、数据及接口方案，列出与现有工程的结合方式；不重新初始化覆盖别人的工作。
2. 建立用户/企业/课程/任务/团队/成员关系/行动记录等概念实体。企业、行政区、团队和课程是不同维度，不以一个字段混用。
3. 建立可信身份、企业隔离和作者权限；前端传入的userId、enterpriseId不能直接作为授权凭据。
4. 实现今日任务查询、记录查询和可测试的写入基础；提交有幂等键、归属校验和权威结果，区分已提交、有效完成、待处理/异常等含义，实际状态集合先形成方案。
5. 早起提供服务端时间/窗口状态与提交校验。通过可注入时钟测试05:30:59、05:31:00、05:31:59、05:32:00。以半开区间[05:31:00,05:32:00)表达，涵盖最后一秒的小数部分。网络延迟、接收时间判定、补卡和重试策略明确列为待决定，不能暗改成宽限时间。
6. 晨跑将文件上传、识别任务、识别结果、用户确认分开设计。OCR尚未选型时提供返回明确模拟标志的测试适配器。不要伪称已识别图片；保留用户修订标志，重复图片/真实性规则待定。
7. 阅读分别保存任务关联、时长申报/计时来源和完成声明；不要仅按客户端秒数认定有效阅读。
8. 拜访记录为自主申报，不声称客户确认或位置验证。正式重复次数政策待定。
9. 后台优先实现有权限的记录查询、按企业/课程/团队/日期/项目筛选、统计与CSV等表格导出。前端后台页面尚未设计，可先提供受保护接口和测试演示，不公开真实员工记录。
10. 排行先定义范围、指标、周期、并列、刷新、资格与跨企业展示字段；未确认前不实现综合得分或用模拟排序当正式算法。

## 5. 接口与数据方案至少应覆盖

这是接口能力清单，不是固定的URL、数据库结构或已存在接口。

| 能力 | 需说明的关键点 |
|---|---|
| 当前身份/归属 | 用户、企业、课程、团队与角色的可信来源 |
| 今日任务 | 业务日期、项目、规则版本、窗口、提交及完成状态 |
| 创建/查找/加入团队 | 课程/企业范围、输入校验、邀请码、加入状态、权限与去重 |
| 提交行动 | 任务标识、幂等键、项目数据、附件引用；服务器校验后返回结果 |
| 图片与识别 | 上传限制/存储权限、处理中/失败/结果、模拟适配器标志、用户确认 |
| 个人记录 | 本人查询、分页、提交与有效状态、时长等指标的来源 |
| 管理查询/统计导出 | 角色和企业边界、过滤条件、统计定义、导出防泄漏 |
| 排行 | 指标、范围、周期、更新时间和未定义规则的处理 |

每项给出输入、返回、错误、鉴权和验收样例。所有项目“完成”定义不能因为页面按钮成功就固定为true。

## 6. 验收与交付

- 用虚构的企业A/企业B及多个测试用户，验证不能跨企业读写、不能替他人打卡或读私密资料。
- 同一个提交重复执行，不生成重复记录；并发加入团队不会重复计数。
- 早起窗口四个边界测试及明确的业务时区；客户端修改时间不改变判定。
- 晨跑记录清楚区分模拟/真实识别、原识别值/用户确认值。
- 阅读时长与任务完成声明分别可查。
- 后台记录和统计导出与测试原始数据可核对；应参与人数/已提交/有效完成不可混为一列。
- 提供可复现启动步骤、测试账号或测试身份方式、自动测试结果和未验证项。
- 每次更新DEVLOG，包含做了什么/为什么/文件变更/验证/未验证/待决/下一步。

## 7. 执行边界

负责人希望WorkBuddy开始后端工作，可先开展本地或隔离测试环境的设计、骨架和可确认能力。此文不代表批准剩余业务默认值、注册主体、购买服务、正式部署、生产数据迁移或跨企业公开数据。遇到未定规则可隔离为待配置/未启用能力，先做不依赖它的部分，不反复停在泛化的“需求未定”。
