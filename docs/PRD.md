# 鸿心徒步小程序重建：产品需求与开发交接文档

- 文档版本：v0.1（现状调研与开发准备稿）
- 编制日期：2026-11-03
- 交付对象：产品负责人、WorkBuddy及开发执行人员
- 现有载体：微信小程序「鸿心徒步」
- 调研身份：普通用户，身份由产品负责人确认
- 当前工作范围：功能结构梳理、重建需求准备；尚未开始开发或部署

> 本文可用于建立开发任务和原型，不是已批准上线的最终规格。本文明确区分已观察事实、重建建议和待确认规则。附录保留全部逐项功能；未查看或未验证的内容不得当作现系统已实现的事实。

## 1. 项目背景与目标

负责人计划重新注册相关账号、重新建设服务器和重新配置小程序平台，并将具体代码开发交给WorkBuddy。当前阶段首先建立现有用户端的功能基线，为后续取舍、页面设计和实现提供依据。账号注册、主体认证、服务器开通和迁移均未执行。

现有业务包括徒步运动、队伍组织、在线课堂、共读打卡、普通笔记、学习笔记、活动动态和个人中心。底部导航为：首页、共读、动态、笔记、我的。

本轮目标：

1. 按页面和功能点梳理已观察的用户端能力。
2. 将排行榜、数据口径、权限与活动状态分别定义，避免同名误用。
3. 标出影响实现的未知项，供负责人集中确认。
4. 给出开发阶段划分与验收方向，支持WorkBuddy形成可追踪任务。

非当前范围：直接操作旧生产系统、复制真实用户隐私数据、自动注册账号、购买服务器、生产部署、执行旧系统删除/报名/打卡。未授权引入付费、考试、积分商城、AI推荐等新增业务。

## 4. 功能需求规格

### 4.1 用户与个人资料（M01–M12）

已观察：个人头像、昵称、累计步数及公里；独立的昵称、姓名、手机号编辑页。昵称文案允许字母/数字/汉字、禁用特殊字符；姓名文案承诺仅自己查看。手机号页包含旧号码、新号码、获取手机号码和保存。

重建建议：公开展示身份与私密资料分开处理；手机号、姓名不进入公开排行或动态。所有保存均有服务端校验、提交中状态、成功/失败反馈；进入编辑页不得自动修改资料。手机号获取、校验和绑定流程待确认，不自行补成短信流程。头像上传规格、昵称长度及重名规则待确认。

### 4.2 徒步与队伍（H01–H11、W01–W32）

已观察：个人今日/累计步数、活动累计步数与公里、参与总人次；队伍发现、名称搜索入口、创建表单、详情、加入与捐步入口；成员总步数榜、今日步数页签、证书入口。

重建建议：将个人步数记录、活动统计和队伍贡献分开建模；同一天多次同步不得无条件重复累加。重复请求应返回稳定结果。步数来源、补传、跨天、退出/转队后的贡献归属必须先确认。创建队伍前显示明确字段要求，提交后结果可追踪。

待确认：每人队伍数量、创建/加入审核、退队、队长管理、有效步数上限、无效步数处理、公里换算、证书条件。队伍口号20字以内为已观察规则，其余创建字段的必填性不能从空表单推定。

### 4.3 在线课堂（C01–C15、H12–H17）

已观察：分类栏目、课程卡封面/标题/讲课时间/已听课人数，在线课堂的成员区、学习广场、我的笔记、学习笔记发布表单。

重建建议：课程内容和笔记关联明确；“已听课人数”的计数触发点单独定义。我的学习与已报名共读是否合并需业务确认。媒体类型、播放、章节、完成条件及进度存储尚未确认，不能默认按完整视频学习系统估工。

### 4.4 共读与打卡（R01–R16）

已观察：书目发现、介绍、参与者摘要、活动起止时间、审核方式、打卡规则、单书打卡排行、已报名列表及开始学习入口。

仅《中庸》已见规则：无需审核，2024-06-13开始、2026-06-13结束，不限打卡次数、不限日记字数、无需图片。其他书目独立配置情况未知。

重建建议：分别表达活动状态、报名状态和学习状态。建议活动至少区分未开始/进行中/结束，报名状态的实际集合根据审核业务确认；页面按钮由状态决定。结束后可否继续阅读、报名、打卡或上榜须明确。打卡次数与累计打卡天数应分别统计；同日多次和补卡如何计天需要确认。

### 4.5 普通笔记与学习笔记（N01–N14、C03–C14）

已观察：两个场景均支持正文、最多三张图片、仅自己可见；普通笔记公开到笔记广场，学习笔记公开到学习广场。列表含作者、时间、内容、图片区域；普通笔记另有已写笔记天数。其他作者卡片可见删除入口，实际执行权限未知。

重建建议：可以复用编辑组件，但保留笔记类型与所属课堂等业务关联，不擅自合并公开列表。私密内容必须在服务端限制访问，不能只隐藏按钮。发布/删除权限、审核、编辑、草稿和恢复策略需确认。图片格式、大小、失败重试与正文长度应形成配置，未定值不得伪装为旧规则。

### 4.6 动态（D01–D05）

已观察：用户头像、昵称、时间、活动名称与步数，当前可见按时间由新到旧，存在零步数记录。

待确认：记录触发源、重复同步是否重复生成、零步数是否进入动态、公开范围、其他动态类型。尚未确认手动发动态、评论、点赞或关注。

### 4.7 反馈与授权（M12–M16）

已观察：意见反馈进入留言板，有200字计数、提交、留言列表，列表含作者、时间、内容、回复/删除入口；其他用户留言可见。不能默认这是私密客服工单。

“微信运动授权”在桌面端打开小程序设置面板，当前可见位置、本地图片/视频保存权限，未见微信运动项。需要手机端复核。

重建建议：先决定反馈是公开留言还是私密反馈；若保留公开留言，明确哪些信息可以公开。回复和删除按角色与作者关系限制。位置、本地保存、运动数据授权分别解释用途与失败路径，不以一个泛化按钮替代全部授权说明。

## 5. 排行榜与统计契约

完整入口表见附录B01–B10，其中B08已分成三个榜。开发不得将所有榜单共用一个未标明范围的“步数”字段。

每个榜单在实现前必须形成以下定义：

| 定义项 | 必须回答的问题 |
|---|---|
| 排名对象 | 用户、队伍还是特定共读的参与者？ |
| 作用范围 | 平台、活动、某个队伍或某本书？ |
| 时间范围 | 当天、活动周期或累计；起点是什么？ |
| 业务时区 | 哪个时区划分一天？建议新版本统一Asia/Shanghai，待确认 |
| 指标 | 总步数、人数、平均步数或有效打卡天数？ |
| 分母 | 平均步数除以全部成员还是有效参与成员？退出成员怎么算？ |
| 排序 | 降序、并列名次、次级排序如何处理？ |
| 更新 | 实时或批量；页面如何展示数据截止时间？ |
| 展示 | 分页、自身名次、未上榜、零值、空榜如何显示？ |
| 纠错 | 撤销记录、重复同步、补卡、转队如何重算？ |

已见样例22054÷13=1696.4615支持平均步数按总步数/人数展示，但不能据单例确认所有分母与时间规则。新实现应使用固定口径的测试数据验算；人数为0时不得出现除零错误。首页队伍步数榜与个人中心队伍榜存在显著数值和排序差异，需分别定义时间与活动范围后再决定复用。

## 6. 角色与权限要求（新版本建议，待确认）

目前只确认普通用户身份，其他角色是待设计的权限分工，不是旧系统调查结论。

| 操作 | 普通用户建议权限 | 其他角色待确认 |
|---|---|---|
| 浏览公开内容与排行 | 按产品公开范围查看 | 企业间是否隔离需确认 |
| 编辑资料 | 仅本人 | 管理员能否代改需单独定义 |
| 查看私密姓名/手机号/笔记 | 仅本人及明确授权的必要处理方 | 不默认开放给队长 |
| 发布笔记/留言 | 本人身份发布 | 审核角色是否存在待确认 |
| 编辑/删除内容 | 原则上仅本人内容，具体政策待确认 | 运营删除需独立授权与记录 |
| 加入/创建队伍 | 按确认后的限制 | 队长和成员管理规则待确认 |
| 更改活动、课程、规则 | 普通用户不开放 | 管理端权限另行设计 |

所有写操作以服务端身份和资源归属校验为准。应使用两个普通测试账号验证横向访问和删除限制；不能通过在旧系统上尝试删除他人内容来验收。

## 7. 概念数据模型（供实现讨论，不是旧数据库结构）

| 对象 | 建议表达的业务信息 | 关键约束/未知 |
|---|---|---|
| 用户与私密资料 | 身份标识、昵称、头像；姓名和手机号分开控制 | 微信身份关联与新旧账号映射待确认 |
| 徒步活动 | 届次、标题、内容、有效时间 | 活动与累计统计边界待确认 |
| 队伍/成员关系 | 活动、封面、名称、口号、城市、发起人；加入与退出时间 | 一人多队与跨活动关系待确认 |
| 步数记录 | 用户、业务日期、来源、同步时间、有效步数 | 快照/增量与贡献归属待确认 |
| 课程/共读活动 | 类型、标题、封面、介绍、规则、时间 | 是否统一内容模型待确认 |
| 报名/学习/打卡 | 用户与内容关系、状态、时间、正文/图片关联 | 去重、完成条件与补卡待确认 |
| 笔记 | 作者、类型、课堂关联、正文、图片、可见范围 | 普通与课堂笔记保持业务区别 |
| 动态事件 | 来源记录、类型、发生时间、公开展示字段 | 来源撤销与去重待确认 |
| 留言/回复 | 作者、内容、时间、关联留言 | 公开范围、删除策略待确认 |
| 证书 | 用户、活动/队伍、达标依据、生成信息 | 功能内部未看，不先固定字段 |

榜单可以由统计结果产生；数据模型应能回溯原始业务记录，而非只保存无法解释的总数。具体数据库、技术栈和缓存方案由WorkBuddy在规则确认后提出。

## 8. 页面状态与交互验收要求（新版本建议）

1. 区分加载中、真实零值、空列表、加载失败、无权限和活动已结束；不将未加载结果展示成真实0。
2. 表单包含明确标签、限制、校验提示；保存/发布进行中避免重复提交，失败后保留输入。
3. 长队名可查看完整内容；图片加载失败有占位；返回不会意外产生写入。
4. 公开/私密范围在发布前可理解，发布后与个人列表一致。
5. 排行页明确指标、范围、周期和更新时间；不同页相同指标在相同范围下数值一致。
6. 登录过期、未授权、网络失败提供可恢复路径；不得将手机端能力在桌面端静默失败。
7. 不在公开笔记、动态、排行和日志中暴露姓名、手机号或敏感凭据。

## 10. 开发阶段与交付物

## 11. 负责人待确认的关键决策

## 十、功能之间的关系

1. **首页**汇总运动数据、队伍榜和课程入口。
2. **徒步活动**承载活动届次与队伍发现；队伍详情承载成员排行、加入、捐步、分享和证书入口。
3. **在线课堂**承载课程相关学习广场与学习笔记；媒体与学习进度仍待核实。
4. **共读**承载书目发现、规则、参与入口、已报名内容与打卡排行。
5. **动态**当前显示运动活动记录；与上传/捐步的触发关系尚未验证。
6. **笔记**承载普通公开/私密笔记，与课堂学习笔记有不同的公开目标。
7. **我的**集中个人数据、各类个人记录、资料、授权和反馈入口。
