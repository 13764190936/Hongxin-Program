# 功能打磨清单（逐功能闭环）

- 日期：2026-11-03
- 约束：**一轮只做一个功能**，做完全链路闭环、验收通过，才进下一个。
- 配套：总体规划见 `docs/PLAN.md`；口径见 `docs/ACTION-METRICS.md`

---

## 1. 节奏约定（先定规则，再谈内容）

### 一轮的边界

| 项 | 约定 |
|---|---|
| 一轮范围 | **一个功能**。允许为了它改组件，但不允许顺手改别的页面 |
| 每轮开始 | 我先给出「本轮要改的文件」和「本轮绝对不动的文件」 |
| 每轮结束 | 提交一次 + DEVLOG 一条 + 一份验收清单（见下） |
| 未通过 | **不进下一个功能**，在同一功能内继续修 |
| 每轮你只需做 | 打开链接，按验收清单点 5–8 条，回「过 / 第 N 条不过」 |

### 「全链路闭环」的定义（每个功能都要走完这七段）

```
① 前端页面与布局
② 交互与事件绑定
③ 请求构造（路径/方法/幂等键/参数/授权头）
④ 后端接收与校验（参数、身份、归属、规则）
⑤ 业务处理与落库（含状态判定、幂等、事务）
⑥ 返回结构（成功体 / 错误码 / 可解释原因）
⑦ 状态回写（UI 刷新点、跨页数据一致性、失败后保留输入）
```

**只做到 ①②③ 叫"画了页面"，不算闭环。** 判断标准：刷新后数据还在，换个角色能看到，出错有可读原因。

### 验收标准写法

每条必须是**可勾选的动作**，不写"体验良好"这种词。例：

- ❌「早起打卡体验流畅」
- ✅「在 05:32:00 点提交，返回 422，页面显示『不在 05:31 窗口内』，且任务卡仍是未完成」

## 3. 逐功能规格

### F00 · 设计基线　P0

**链路范围**：纯前端，无接口。

- ① `tokens.css`：字号 6 级（11/12.5/14/16/20/26）、间距 4 的倍数、圆角 3 档（8/14/22）、语义色四组
- ② `base.css`：重置、排版、工具类
- ③ 8 个组件：行动卡、榜单行、底部弹层、按钮、输入框、空态、骨架屏、步骤条
- ④ `/gallery` 页：把 8 个组件的**所有状态**铺开
- ⑤ 自测脚本：扫描 `pages/**` 是否出现 `#` 颜色值或 `px` 字号，出现即失败

**验收**

1. `/gallery` 能打开，8 个组件全部有展示
2. 行动卡 6 种状态（未完成/已完成/待核/未到时间/已错过/加载）肉眼可区分
3. 榜单行 5 种（前三/普通/我/并列/空）可区分
4. 空态三套（无数据/无权限/网络失败）各有插画与主行动按钮
5. 令牌自测脚本通过（`pages/` 零硬编码）
6. 320px 宽无横向滚动

### F01 · 今天页　P1

**链路范围**

- ① 顶部进度卡（4 段进度）+ 四张行动卡 + 今日阅读
- ② 点击卡片进对应详情；下拉刷新；tab 切回不丢状态
- ③ `GET /api/today`（已有）、`GET /api/me`（已有）
- ④ 后端无需改：按用户 + 企业返回当日任务与记录
- ⑤ —（读链路）
- ⑥ 返回 `{bizDate, tasks:[{kind,done,records,rule}]}`
- ⑦ 写回点：任一详情页提交成功后回到本页，卡片立即变「已完成」并更新进度段

**现有缺陷**：进度条 3px 无线索；卡片无图标；无剩余数量引导；下拉不刷新。

**验收**

1. 首次进入显示骨架屏 → 内容出现（不闪 0）
2. 四张卡的状态与数据库一致（切换身份后仍一致）
3. 提交任一行动后返回本页，该卡 1 秒内变已完成、进度段亮起
4. 下拉刷新后数据重新拉取，无重复记录
5. 网络失败显示错误态 + 重试按钮，重试成功恢复
6. 未加入团队时顶部不显示团队名，且不报错

### F02 · 早起打卡　P1

**链路范围**

- ① 服务器时间与本地时间并列；窗口 `05:31:00–05:31:59`；前后 5 分钟倒计时
- ② 按钮可用性由窗口决定；点击弹确认层
- ③ `POST /api/actions`：`kind=early`、`claimedAt`（客户端点击时刻）、`idempotencyKey`
- ④ 后端校验：身份、课程归属、窗口（半开区间、北京时间）
- ⑤ 窗口内落库 `valid`；与服务端偏差 >180s 落库 `pending_review`；窗口外 **422 不落库**
- ⑥ 成功 `{record}`；失败 `{error:{code,message}}`，code 含 `early_out_of_window`
- ⑦ 写回：卡片变已完成、榜单 `early_count` +1、`/api/today` 再次查询一致

**后端增量**：新增 `GET /api/server-time` 返回服务器时间与当前窗口状态（避免前端用本地时钟推断）。

**验收**

1. 页面同时显示「服务器 05:31:12 / 本机 05:31:09」，并注明以服务器为准
2. 窗口外按钮禁用并显示倒计时到明日 05:31
3. 直接调接口在窗口外提交 → 422，数据库无新增（可用 `/api/records` 核对）
4. 窗口内提交 → 卡片变已完成，榜单该人 +1
5. 连点两次（同幂等键）→ 只有一条记录
6. 把本机时间改到 05:31 提交 → 记录落库但状态是「待核」，卡片显示待核而非已完成
7. 刷新页面，状态与记录号仍在

### F03 · 阅读打卡　P1

**链路范围**

- ① 正文/示例文本区 + 圆环计时（目标 15 分钟）+ 完成勾选 + 保存
- ② 开始/暂停/结束；离开页面前提示；勾选与时长独立
- ③ `POST /api/actions`：`kind=read`、`payload.readSeconds`、`payload.completed`
- ④ 后端校验：`readSeconds ≥ 60`，整数；`completed` 布尔
- ⑤ 落库 `valid`；`completed=false` 时仍有效但指标记录为未完成
- ⑥ 成功/`read_too_short`(422)
- ⑦ 写回：圆环、进度、榜单 `read_minutes`、我的记录

**现有缺陷**：先结束才能勾选（顺序反了）；无正文；退出无提示；计时器切 tab 会停但界面不说。

**验收**

1. 计时 60 秒后「保存」才可点，之前禁用并提示原因
2. 暂停→继续，时长连续不重置
3. 切到别的 tab 再回来，页面明确显示「计时已暂停，当前 03:12」
4. 不勾选完成直接保存 → 记录有效但「任务」列显示未完成
5. 保存后圆环停止、卡片变已完成、榜单分钟数增加
6. 手动改接口传 `readSeconds: 30` → 422，不落库

### F04 · 晨跑记录　P1

**链路范围**

- ① 三步：选图 → 识别/确认 → 提交；图片真实预览
- ② 选图、重选、删除；数据可编辑并标出"用户改过"
- ③ `POST /api/uploads`（新）→ 返回 `imageRef`；再 `POST /api/actions`
- ④ 后端校验：图片类型/大小、距离>0、时长≥1、步数正整数
- ⑤ 落库；因 OCR 未接，`ocrMock=true` → 状态 `pending_review`
- ⑥ 返回 `record` 与 `reviewReason: ocr_is_mock`
- ⑦ 写回：卡片变「待核」；榜单**不计入**；提示"待人工确认后计入"

**后端增量**：图片上传接口 + 云存储/本地目录；`image_ref` 落库。

**验收**

1. 能选中本地 JPG/PNG 并在页面上看到预览
2. 选非图片文件被拒并说明原因
3. 三步可回退，回退不丢已填数据
4. 提交后卡片显示「待核」且页面明说"识别未接入，不作数"
5. 榜单 `run_km` 不因这条记录变化
6. 换账号用同一张图提交 → 不报错（重复图片规则未定，明确写"未校验"）

---

### F05 · 拜访记录　P1

**链路范围**

- ① 说明区（是什么/为什么记/谁看得到）+ 记录按钮
- ② 点击 → 确认弹层（显示"将记录：今天 1 次"）→ 确认
- ③ `POST /api/actions`：`kind=visit`
- ④ 校验：同一天第 2 次 → 409
- ⑤ 落库 `valid`，不进排行
- ⑥ 成功 / `visit_daily_limit`(409)
- ⑦ 写回：显示"今日已记录 1 次 · 14:32"

**验收**

1. 确认弹层文案与实际记录行为一致
2. 首次记录成功，页面显示次数与时间
3. 当天第二次 → 409，页面说明"每日 1 次（当前默认，待确认）"
4. 该记录不出现在任何榜单
5. 主管视图能看到这条，标注"自主申报"

### F06 · 排行榜　P1

**链路范围**

- ① 范围（小组/企业）× 指标（早起/晨跑/阅读）× 周期（今天/本周）
- ② 切换即请求；我的名次常驻吸底
- ③ `GET /api/rankings?scope&metric&period`
- ④ 后端：`metric` 白名单、`scope` 白名单、`status='valid'`
- ⑤ 聚合 + 并列同名次
- ⑥ 返回 `{metricLabel, unit, from, to, rows:[{rank,name,value,isMe}], note}`
- ⑦ 写回：切换时骨架屏，数据回来替换；未入队返回空榜 + 引导

**后端增量**：`rows` 补 `avatar`（首字色块可前端算，但需要稳定 key）；并列需返回 `tied:true`。

**验收**

1. 六个组合（2 范围 × 3 指标）都能出数据或明确空态
2. 我的行固定可见并高亮
3. 同分显示并列，下一名跳号
4. 切换时先出骨架屏，不出现旧数据残留
5. 未入队查小组榜 → 空态 +「去加入团队」
6. 待核记录不计入（用晨跑验证）

---

### F07 · 团队　P1

**链路范围**

- ① 我的团队（成员头像墙、邀请码、我的角色）
- ② 创建 / 按名称或邀请码查找 / 加入 / 复制邀请码
- ③ `GET /api/teams`、`POST /api/teams`、`POST /api/teams/:id/join`、`POST /api/teams/join-by-code`（新）
- ④ 校验：同名冲突、已在他队、跨企业、邀请码无效
- ⑤ 落库 `team_members`
- ⑥ 成功 / `team_name_taken`(409) / `already_in_team`(409) / `cross_enterprise`(403)
- ⑦ 写回：加入后首页与榜单立刻出现团队维度

**后端增量**：邀请码加入接口；成员列表接口（含角色、加入时间）。

**验收**

1. 能创建团队，创建者角色显示「创建者」，成员数 1
2. 创建同名 → 409 并给出原因
3. 用邀请码加入他人团队 → 成功，成员数 +1，双方都能看到
4. 已在队中再加入 → 409，不擅自转队
5. 跨企业邀请码 → 403
6. 加入后小组榜出现自己的名字

## 4. 横切项（每个功能都要顺手满足，不单列一轮）

| 项 | 要求 |
|---|---|
| 五态 | 加载 / 空 / 错误 / 无权限 / 成功，每页都有 |
| 防重复提交 | 按钮 loading + 幂等键 |
| 失败保留输入 | 表单失败不清空 |
| 时间 | 一律北京时间字符串，不吐 UTC |
| 可解释错误 | 不弹 `error.code`，弹人话 |
| 自测 | 每轮至少新增 3 条自动化检查 |
